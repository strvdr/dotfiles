
# dotfiles

These are my dotfiles. They are primarily for my personal use, but feel free to use them as you wish.

Arch + Hyprland, running [HyDE](https://github.com/HyDE-Project/HyDE).

## Layout

GNU Stow packages — each top-level directory mirrors the path it installs to
relative to `$HOME`:

```
hypr/.config/hypr/      hyprland, keybindings, windowrules, monitors,
                        userprefs, workspaces, hypridle, nvidia, hyde
fish/.config/fish/      config.fish
kitty/.config/kitty/    kitty.conf, theme.conf
dunst/.config/dunst/    dunst.conf
nvim/.config/nvim/      LazyVim config (lazy-lock.json pins plugin versions)
starship/.config/       starship.toml
tmux/                   .tmux.conf
```


## Installation

Ensure that you have stow installed. This varies depending on your package manager.
Change to the directory you just cloned, and stow any dotfiles you want to use.

arch, btw:

```bash
  sudo pacman -S stow
  git clone https://github.com/strvdr/dotfiles.git ~/dotfiles
  cd ~/dotfiles
  stow hypr fish kitty dunst nvim starship tmux   # or: stow */
```

Stow refuses to overwrite existing real files. On a machine that already has
configs, either move them aside first or use `stow --adopt <pkg>` — that pulls the
existing file into the repo, so check `git diff` afterwards to see what it absorbed.

To remove a package: `stow -D <pkg>`.


## What is deliberately NOT tracked

HyDE generates a lot of config from the active theme and wallpaper. Tracking those
files means a merge conflict every time you switch themes, so they are gitignored:

| File | Owner |
|---|---|
| `dunst/dunstrc` | generated by `wallbash/scripts/dunst.sh` — edit `dunst.conf` instead, then `hyde-shell wallbash dunst` |
| `fish/hyde_config.fish`, `fish/conf.d/fish_frozen_*.fish` | HyDE |
| `kitty/hyde.conf` | HyDE (included from `kitty.conf`) |
| `.config/hyde/`, `hypr/themes/`, `hypr/animations/`, `hypr/hyprlock/` | HyDE |
| `waybar/`, `rofi/`, `wlogout/` | HyDE — regenerated per theme |
| `fish_variables` | fish rewrites this itself |

`hypr/hyprlock.conf` and `hypr/animations.conf` are untouched HyDE defaults and are
not tracked. If you customize either, move it into `hypr/.config/hypr/` and re-stow.


## Caveat: HyDE updates vs. symlinks

HyDE's updater may *replace* files under `~/.config/hypr` rather than writing them
in place. If it replaces one, the symlink is removed and that file silently stops
being tracked. After a HyDE update, check that nothing has detached:

```bash
  ls -l ~/.config/hypr/*.conf ~/.config/fish/config.fish \
        ~/.config/kitty/*.conf ~/.config/dunst/dunst.conf | grep -v ' -> '
```

Anything listed is a real file where a symlink is expected — re-stow that package.
